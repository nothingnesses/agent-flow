### `workflow-driver-typed-fleet`: build the workflow driver's typed per-unit fleet on the compact Q-58 carrier (`Q-82`, Stage 2)

This step implements the existing Stage-2 architecture; it does not redesign it. The authoritative scope is the Stage 2 paragraph in `docs/plans/agent-scaffold.steps/workflow-driver.md`, with the detailed build path in `docs/plans/mealy-workflow-driver.explorations/r2-synthesis.md` and `r2-architecture-build-path.md`. Q-82 schedules it after the independent visibility repair.

DEPENDENCIES ARE LOAD-BEARING. `structured-risk-class-source`, reached through the direct `workflow-loop-visibility` dependency and independently through `review-loop-foreclosure-enforcement`, establishes the exact increment-id compatibility arm, task-loop class declarations and one active-loop selector. `workflow-loop-visibility` then completes the typed task/question/step active-work union, phase-correct plural projection and pending compatibility fallback without forking that selector. `q58-output-ablation` must select the compact carrier, and `resume-state-currency-signal` must add Q-59's currency value to it. `review-loop-foreclosure-enforcement` must land the reviewed ordered loop-window reconstruction shared by W3 and `next`, including escalation segmentation, both authoritative declaration arms and snapshot matching, exact selected identity, streak, convergence-first precedence, foreclosure and cap state. The TOML `blocked_by` edges preserve those prerequisites: visibility and foreclosure are direct, and Q-58 is transitive through `resume-state-currency-signal`. This step consumes those reviewed substrates; it does not assume structured-only before the experiment, restore a prose echo by convenience or extract a second copy of a declaration join, selector or loop formula.

THE SCOPE. Extend the shared loop-window reconstruction delivered by `review-loop-foreclosure-enforcement` with the Stage-2 `src/driver/` fleet: a total `ReviewLoop` Mealy transition, nested `TaskMachine`, `QuestionMachine` and `StepMachine`, full reconstruction of every typed active unit, and instruction emission from typed state. The fleet may wrap or enrich the earlier reconstruction's typed result, but W3, `next` and the fleet call the same implementation for round order, escalation windows, authoritative Roadmap/task declaration lookup, snapshot agreement, active Roadmap increment selection, streak, cap, foreclosure and convergence. Judgments enter only through typed inputs; no transition manufactures a triage verdict, risk class or human decision. Preserve `workflow-loop-visibility`'s complete task/question/step collection, exact step/increment identity, pending compatibility fallback and one selected action until the scheduler deliberately replaces only that fallback.

THE BOUNDARY. No ready-frontier scheduling, parallel fan-out, record/write commands, persistent FSM store or workflow DSL. `workflow-ready-frontier-scheduler` owns the first item; the others retain the YAGNI boundary in `workflow-driver`.

### Increment 1, `workflow-driver-typed-fleet-inc1`

RISK CLASS `risky` (two consecutive clean review rounds). The typed engine becomes the common source for checker and driver state and controls the instruction an agent receives. A divergence can either waive required review or deadlock legal work.

ACCEPTANCE.

1. W3, Stage-1 `next` and the fleet call the reviewed reconstruction delivered by `review-loop-foreclosure-enforcement` for ordered records, escalation/adoption segments, authoritative Roadmap-increment and task-plan-review declarations, exact selected Roadmap increment, round-snapshot agreement, streak, cap, foreclosure and convergence. No second formula, declaration lookup or open-increment selector exists under `src/driver/`. A differential suite replays logs and compares the fleet's enriched forward state with the earlier reconstruction and backward validator verdict.
2. The transition table is total at compile time: every `(state, input)` pair has a defined result or typed rejection, and adding a state/input variant makes the exhaustive test fail to compile until handled.
3. Every output requiring judgment is reachable only from an input carrying that judgment. Red mutations that synthesize a clean verdict, risk class or human choice fail.
4. Reconstruction returns every task-, question- and step-scoped explicit active unit and preserves each phase established by `workflow-loop-visibility`. Legal plan-review fixtures stay task-scoped and resolve a `[[task_loop]]`; acceptance/review stay task-scoped single passes without convergence arithmetic; Q-68/Q-69-shaped exploration stays question-scoped with no Roadmap owner; each step unit retains its exact declared increment; pending `ready-to-plan`/`blocked` remains a typed fallback until Stage 3. No lowest-order active-work filter sits below the fleet; the singular selected action is derived from the explicit collection first and the fallback only when that collection has no actionable unit.
5. The selected Q-58 carrier supplies non-derivable `awaiting`, artifact/diff and currency data through a typed boundary. Missing, stale and dirty states are explicit; heuristic prose parsing is forbidden unless the Q-58 decision explicitly selected and bounded a parser, in which case that exact parser is the typed boundary.
6. Golden human and JSON fixtures cover: a pre-round risky task plan review and a mismatched low-risk snapshot; task-scoped acceptance and standalone review without convergence-loop inheritance; question-scoped exploration without a Roadmap step; step-scoped exploration, implementation and work review; a converged low-risk increment beside the explicitly selected zero-round risky sibling; pending ready/blocked fallback; first review, fixes, reviewer continuation, convergence, foreclosure/cap escalation, missing/mismatched declarations and terminal states; and multiple simultaneous units. No fixture obtains a task phase by changing an implementation step's status, a question exploration by borrowing an unrelated step, or an open increment from declaration order/latest round.
7. Existing W3/W4/W5 tests and Stage-1 output fixtures remain green or receive reviewed, documented contract migrations. No scheduler or write path appears in the diff.
8. README documents typed reconstruction and the unchanged advisory/read-only authority; `CHANGELOG.md` records the Stage-2 engine. Any pack guidance made stale by emitted-state vocabulary moves with its committed copies.
9. Both validation modes, strict render, tests and differential/red controls, Clippy, diff checks and ASCII checks pass.
